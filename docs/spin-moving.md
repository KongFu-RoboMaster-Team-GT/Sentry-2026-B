# 原拨杆小陀螺行进

用户已确认CAN1发送修正后普通行进流畅。本轮保留这份上板固件，完成原小陀螺开关下的行进解算修正和回归；没有代用户烧录或完成实车旋转测试。

## 操作

原遥控ch7拨杆（接收机原映射到`key.pause`）保持不变：通道解析结果大于0开启，其他位置关闭。接收机解码、通道选择和上板协议3均未修改。

| 小陀螺拨杆 | 右摇杆 | 期望行为 |
|---|---|---|
| 关闭 | 前后/左右 | 原普通行进，底盘跟随仍由原跟随开关决定 |
| 开启 | 回中 | 平移缓降到零，继续原地小陀螺 |
| 开启 | 前后/左右/斜向 | 底盘自旋，同时沿枪口坐标系行进 |
| 从开启切回关闭 | 任意 | 退出小陀螺，按原普通/跟随逻辑运行，保留角速度缓变 |

跟随与小陀螺同时开启时，小陀螺优先，跟随积分清除。退出小陀螺后，如果跟随拨杆仍开启，底盘会按原逻辑对齐枪口；并非要求立即停止一切旋转。键鼠Shift仍为原小陀螺控制。

LOWER目标自旋速度集中到`User/control_config.h`的`CHASSIS_SPIN_OMEGA_RPS`，沿用原6.2831853rad/s（目标约1圈/秒）及原旋转方向。角速度缓变仍为8rad/s²，正常起旋/停旋约0.79秒；实际转速取决于负载、电机和速度环。

## 为什么修改坐标缓变顺序

原代码已经将平移与自旋叠加，但先转换成底盘坐标，再限制底盘坐标vx/vy的变化率。底盘旋转时，即便枪口坐标平移请求不变，底盘坐标分量也必须随相对yaw角变化；后置限速会阻碍这种坐标基变化，使行进方向滞后。

本轮LOWER改为：

```
原遥控轴 → 枪口坐标平移缓变 → 按实时yaw编码器转到底盘坐标
                                      ↓
                    与原自旋角速度叠加 → 四轮逆解 → 原速度环
```

平移状态由`chassis_vx_applied/chassis_vy_applied`更名为`gimbal_vx_applied/gimbal_vy_applied`，正常停车与断流复位使用同一份枪口坐标状态。摇杆变化仍沿用原最大分量缓变参数1.5，不能把它解释为所有坐标系下车体实际合加速度的绝对上限。

不修改轮序、几何尺寸、减速比、输出方向、PID增益、输出上限、100ms通信/反馈保护。上板CAN1自动重发、操作帧优先入队和过期待发帧取消全部保留。

## 验证

- 新增坐标回归在旧版明确失败，修正后验证0°、90°、180°、-90°及回到0°时，平移与自旋同时正确；用正解从四轮目标恢复平移和角速度核对。
- 运行实际CHASSIS_TASK，使用协议3的原pause位，覆盖行进中开小陀螺、900ms缓起旋、四象限方向变换、同时开启跟随时自旋优先、松杆后继续原地旋转、关闭拨杆缓停，再次开启过程中输入失效立即四轮归零。
- 既有普通行进、停车、CAN1发送修复回归保留。结果：SINGLE 21、UPPER 4533、UPPER_GUARD 3542、LOWER 18429个断言通过。
- 上下板Keil均0错误、0警告。测试替身编译仍有已有及测试专用未使用变量警告。
- 测试的三角函数替身只覆盖四个基准角，不是实际连续角度/电机惯量/轮胎动力学仿真。需要实车确认旋转过程中的方向和稳定性。
