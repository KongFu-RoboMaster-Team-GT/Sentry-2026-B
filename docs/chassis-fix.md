# 底盘控制修复

本轮基于`docs/chassis-audit-2026-11-14.md`的代码复现结果修复LOWER，并根据随后实机“回中仍抖动”的反馈补充停车释放保持及最长制动时间。审查报告描述的是修复前状态；以本文和当前源码为准。未进行硬件烧录或实车验证。

## 行为变化

- 新增`User/chassis_control.h`，仅LOWER底盘调用。输出饱和时拒绝继续朝饱和方向积分，允许积分解饱和；每个轮子的目标过零或反向时清除旧积分。共享`alg_pid.c/h`不变，底盘Kp=0.95/Ki=0.1/Kd=0及±8192最终输出上限不变。
- 跟随进入2°死区、退出跟随或进入小陀螺时清积分；越过角度零点时清旧积分，避免对齐后仍残留旋转指令。角度符号和原跟随增益不变。
- 遥控轴保留±20死区，死区外改为连续映射；按项目实测783通道单位作为对称满量程，保留满杆783/660≈1.186m/s目标并限制越界输入。中间杆量响应会略有变化；反向端点及横移端点仍需实机核对。
- 正常回中先完成目标减速，再闭环制动；四轮电机轴速度均低于1rad/s（约9.55rpm），或目标归零后的制动达到300ms，即发零并清积分。退出后保持零输出，反馈扰动不能重新启动制动，只有新的非零运动请求能恢复。修正上一版“释放后因速度扰动重新制动”及“零参考一直无法稳定时持续制动”的遗漏。300ms为临时停车制动上限，不是实车制动距离保证；退出后可滑行，不提供静态驻车。持续小输入仍可连续控制，不另设0.02m/s断点。通信断流依旧立即发零，绕过正常停车制动。
- 单轮反馈从未出现或超过原100ms超时，该轮输出归零并清积分；新鲜反馈恢复后恢复该轮闭环。其余轮子仍可控制，不等待全部电机上线。yaw反馈年龄仅供诊断，本轮未增加yaw反馈对全车的解锁门槛。

## 下板Watch

| 字段 | 含义 |
|---|---|
| `lower_diag.feedback_age_ms[0..4]` | 四轮及yaw反馈年龄，单位ms；从未接收为0xFFFFFFFF |
| `lower_diag.stale_wheel_mask` | 轮1–4反馈无效位图；正常应为0 |
| `lower_diag.wheel_saturation_count[0..3]` | 各轮达到PID输出上限的循环累计次数；按运动时间看增量 |
| `lower_diag.braking` | 正常回中后的闭环减速/制动阶段 |
| `lower_diag.idle_latched` | 为1表示已退出闭环，保持零输出直到新的运动请求 |

| `chassis_motion.wheel_target_omega/wheel_now_omega` | 电机轴目标/反馈，单位rad/s |
| `lower_diag.chassis_command[4]` | 最终请求发送的四轮指令；不代表已获电机ACK |

## 回归与构建

`tests/run_protocol.py`增加底盘饱和两秒后积分不增长、反向/过零制动符号、低误差仍积分、反向积分解饱和、跟随零点/死区/退出清积分、遥控中心连续性与端点限幅、四轮停车条件，以及在实际CHASSIS_TASK中运行的停车制动→释放→重启→单轮反馈超时→恢复→通信断流场景。

SINGLE 21、UPPER 4493、UPPER_GUARD 3502、LOWER 1104个断言通过；Keil上下板编译均为0错误、0警告。补充回归先在上一版因轮速扰动重启制动而失败，再验证保持零输出及制动超时通过。测试替身编译仍有原有的文件结尾/未使用变量等警告，不能与Keil固件编译日志混为一谈。

停车修正固件为`firmware/LOWER.hex`；新增摩擦轮/CAN只读诊断固件为`firmware/UPPER.hex`，两板协议仍为3。构建不执行Flash下载。首轮修复前备份在`MDK-ARM/build/chassis-fix-backup/LOWER.hex`，本次回中跟进前两板备份在忽略目录`MDK-ARM/build/esc-followup-backup/`。

该停车修正轮次LOWER.hex SHA256：`2A2D36A6CB5D9A80FA13F76BD808A7E59EB368709DBC0C021CD8AB71B1023563`。随后持续前推诊断版的最新固件与验证记录见`chassis-stutter-diagnostic.md`，当前`firmware/LOWER.hex`已更新为诊断版。

## 实车验证边界

先架空底盘、关闭跟随/小陀螺和发射，用小杆量核对前后左右及回中制动，再落地低速验证。四轮运动学矩阵、轮序、输出符号没有改动，实际安装极性仍需核对。

本轮修复确认的软件缺陷，尚不能保证已消除实车全部抖动。若目标平滑、反馈新鲜，但输出仍反复正负打满，应根据同一时间轴的轮速/指令记录继续调底盘Kp；当前没有实测依据盲改增益。若反馈年龄突增、CAN2发送失败或Bus-Off计数增长，优先处理总线。

1.5m/s²缓变保持，所以+1→-1m/s目标仍需约1.33秒；这是设定的加速度响应，与反复抖动分开验证。本轮没有为追求响应速度直接增大驱动力或加速度。
