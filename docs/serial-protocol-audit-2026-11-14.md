结论：**当前固件不支持这份 AA 55 命令协议，不能直接按文档联调。** 本次只诊断，没有修改控制代码、构建发布固件或烧录。

## 现有接口与差异

当前上位机入口是 USB CDC 虚拟串口：`USB_DEVICE/App/usbd_cdc_if.c:263` 通知 `Task/usbreceive_task.c`，后者调用 `User/PC/motion.c:11`。

现有 `AnglePacket_t` 是紧凑的 11 字节结构：

```
AA | yaw(float32 LE,4) | pitch(float32 LE,4) | flag(1) | FF
```

解析器只检查 AA 和固定偏移处的 FF，没有 CMD、LEN、累加和，也没有命令分发。USB 接收任务在 UPPER/SINGLE 创建，LOWER 不创建该任务。联调应接上板；下板虽初始化 USB，却没有对应接收任务，回调也未检查任务句柄。

| 文档要求 | 当前实现 | 联调结论 |
|---|---|---|
| AA 55 / CMD / LEN / DATA / SUM8 | AA / 9 字节数据 / FF | 帧格式不兼容 |
| 0x01，9 字节 yaw/pitch/fire；空数据应答 | 只有旧包中的相似字段；没有 0x01 处理和应答 | 未实现此命令 |
| 0x02，查询裁判信息并返回 health/fire_number/heat/ZoneIsOurs/Stop | 有独立裁判接收模块，无上位机查询/封包路径 | 未实现 |
| 0x03，返回相对开机朝向及 fire_status | 没有命令、开机参考回传或应答封包 | 未实现 |
| 0x04，设置 stop，无应答 | 没有上位机 stop 的解析、状态或执行门控 | 未实现 |

全项目业务代码未发现 `CDC_Transmit_FS()` 调用，只有函数定义与声明；不能把 USB 底层具有发送函数理解成已经实现状态回传。

现有物理 UART 分配：USART1 为 VTM（961200，8N1），USART3 为遥控接收机（100000，配置 9 位含偶校验、2 停止位），USART6 为裁判系统（115200，8N1）。这些入口都不是这份协议。USB CDC 的应用帧格式仍需单独实现，不能靠改串口工具的波特率解决。

## 已确认的软件缺陷

1. `Task/usbreceive_task.c:12` 忽略 `usbreceive()` 返回值，随后直接访问 `pAngleData->yaw/pitch/flag`。指针初始为 NULL，每次正常处理后也被设回 NULL。新协议、短包、错误包会走到空指针解引用，可能读出错误数据或触发异常，不能安全试发。
2. `User/PC/motion.c` 不缓存半帧，只扫描当前回调的数据，并只处理第一个匹配包。USB 数据分段或一次携带多帧时，存在丢包；回调重新挂接同一接收缓冲区后，任务读数据也缺少独立队列/快照保护。
3. USB 接收写 `usb.auto_fire_flag`，射击逻辑 `Task/shooter_task.c:93` 读 `motion.auto_fire_detect`。未找到把两者连接起来的赋值。因此解析到 flag 不代表自动开火能执行。
4. `Task/gimbal_task.c:377` 附近只有键鼠模式且鼠标右键按下时，才把 `usb.deltaYaw/deltaPitch` 加到目标角；随后清零。这是相对角增量，并非收到数据后无条件设定绝对角。文档未充分定义 yaw/pitch 的参考系、正方向、单位及是否增量，联调前需统一。
5. 目前没有针对这份上位机协议的急停及开火指令有效期。已有遥控/板间超时不能替代 0x04 的明确执行语义。

## 文档示例存在两处数值错误

用 Python `struct.pack('<ffB',12.5,-3.75,1)` 核算：

- -3.75 的 float32 是 `0xC0700000`，小端字节为 `00 00 70 C0`。
- 文档的 `00 00 78 C0` 实际为 -3.875；保留文档这组数据时，累加校验应是 CC，也不是文档写的 C9。

要求 yaw=12.5、pitch=-3.75、fire=true 时，正确完整帧是：

```
AA 55 01 09 00 00 48 41 00 00 70 C0 01 C4
```

该报文仅用于确认字节格式，当前固件尚不能安全执行它。

按现有文字定义，空请求可以写为 `AA 55 02 00 02`、`AA 55 03 00 03`；急停 true 为 `AA 55 04 01 01 06`，stop=false 为 `AA 55 04 01 00 05`。这些同样不是当前固件已支持的命令。

## 实现前需要固定的规格

- 若 0x02 中两个 int 固定为 int32 LE、float 为 float32 LE、bool 为 1 字节，则响应 DATA 长度为 14，整帧 19 字节；文档目前没有明确 int 位宽，不能直接依赖 C 结构体默认布局。
- 0x03 的 DATA 长度应为 5、整帧 10 字节；target 是测量朝向相对开机参考的差，还是控制目标，必须统一。
- fire_number 是剩余弹量还是累计发射数，heat 是裁判实时值还是预测值，ZoneIsOurs 对应哪块区域，需要明确。已有裁判结构包含 HP、17mm 剩余弹量、热量、比赛阶段，但不能据名称直接替代语义确认。
- Stop（比赛阶段派生字段）与 0x04 stop 是否独立、急停是否锁存、解除方式、覆盖底盘/云台/发射哪些部分，需要定义。
- 确定传输为上板 USB CDC，或指定新增硬件 UART；接收需要处理拆包、粘包、坏帧重同步、LEN 校验、非有限 float 和发送忙重试。
